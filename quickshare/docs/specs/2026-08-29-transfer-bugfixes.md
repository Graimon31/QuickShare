## BUG-01. Получатель iOS не фиксирует завершение передачи

**Окружение:** отправитель macOS 15.5, получатель iOS 18.5.1.
**Транспорты:** Wi-Fi (LAN), Bluetooth, интернет — воспроизводится на всех трёх, **включая самую первую передачу** (не связано с повторностью).

**Шаги:**
1. Отправить файл с macOS на iOS по любому транспорту.
2. Дождаться статуса «Завершено» на отправителе.

**Фактический результат:** отправитель показывает «Завершено». На iOS прогресс замирает на 98–100 %, терминальный статус не выставляется. Файл физически передан целиком. На время зависания отображаемая скорость деградирует (наблюдалось вплоть до ~500 КБ/с) — первоначально это было заведено как отдельный дефект скорости (BUG-02).

**Ожидаемый результат:** после получения последнего байта и успешной записи файла получатель переводит передачу в терминальный статус «Завершено», прогресс = 100 %.

**Критерии приёмки:**
- **Given** передача macOS → iOS по транспорту T (T ∈ {Wi-Fi, Bluetooth, интернет}), **When** отправитель получил подтверждение доставки всех данных, **Then** на iOS статус передачи = «Завершено» и прогресс = 100 % не позднее 2 с после этого события.
- **Given** зависания нет, **Then** отображаемая скорость на приёмнике не деградирует без физической причины.

**Для разработки:** проверить цепочку события завершения на iOS-приёмнике (финальный ACK / контрольная сверка / закрытие канала) — какое событие переводит состояние в «завершено» и где оно теряется. Если после исправления завершения деградация скорости при повторных передачах сохранится — завести отдельный дефект с шагами воспроизведения.

## BUG-02. Закрыт формулировкой

Поглощён BUG-01: наблюдавшееся «падение скорости при повторной передаче» трактуется как следствие зависания прогресса на 98–100 %. Самостоятельной работы нет; условие воскрешения — в примечании к BUG-01.

## BUG-03. Удалить строку Wi-Fi-адреса со страницы передачи (desktop)

**Фактический результат:** на desktop-странице Wi-Fi-передачи (QR) отображается строка «Wi-Fi-адрес» вида `192.168.x.x:8080` с кнопкой копирования.

**Ожидаемый результат:** строка Wi-Fi-адреса удалена из UI. Остальные элементы страницы (заголовок-подсказка, QR-код, Room Link, блок файла с размером, таймер сессии, кнопка «Отмена») остаются без изменений. Внутренняя логика соединения не затрагивается.

**Критерии приёмки:**
- **Given** открыта страница Wi-Fi-передачи на desktop, **When** сессия создана, **Then** в UI отсутствует строка с `ip:port`; Room Link присутствует.

**Для разработки:** элемент — `_copyRow` с `qrDisplayWifiAddressLabel` в `lib/features/sender/presentation/pages/qr_display_page.dart`; ставшие неиспользуемыми ключи локализации удалить. Аналогичное отображение адреса на iOS удаляется в рамках BUG-06.

## BUG-04. QR формируется при отключённом Wi-Fi (iOS-отправитель)

**Окружение:** отправитель iOS 18.5.1. Речь о пункте «Wi-Fi / Local Network» на экране выбора способа передачи.

**Шаги:**
1. Выключить Wi-Fi-модуль на iPhone.
2. Выбрать «Wi-Fi / Local Network».

**Фактический результат:** QR-код формируется сразу.

**Ожидаемый результат:** выполняется проверка предусловия (FR-CONN). При выключенном Wi-Fi — запрос включить Wi-Fi (с переходом в настройки, где платформа позволяет). При отказе — сообщение «Передача невозможна, пока не включён Wi-Fi»; сессия, QR и Room Link не создаются, страница подключения не открывается.

**Критерии приёмки:**
- **Given** Wi-Fi-модуль выключен, **When** пользователь выбирает «Wi-Fi / Local Network», **Then** показан запрос на включение Wi-Fi; сессия не создана.
- **Given** показан запрос, **When** пользователь отказывается, **Then** показано сообщение «Передача невозможна, пока не включён Wi-Fi»; пользователь остаётся на экране выбора способа.
- **Given** показан запрос, **When** пользователь включил Wi-Fi, **Then** повторный выбор пункта создаёт сессию и QR штатно.

**Для разработки:** программного переключателя Wi-Fi ни на iOS, ни на macOS нет — только диалог + переход в настройки. Сценарий хотспот-fallback (`NetworkFallbackPage`/`LocalNetworkPage`) данным требованием не затрагивается.

## BUG-05. Сессия создаётся после отказа включить Bluetooth

**Окружение:** отправитель iOS 18.5.1.

**Шаги:**
1. Выключить Bluetooth.
2. Выбрать передачу по Bluetooth → предупреждение с предложением включить Bluetooth.
3. Отказаться.

**Фактический результат:** страница подключения открывается несмотря на отказ.

**Ожидаемое поведение:** при отказе пользователь остаётся на экране выбора способа; сессия, QR, Room Link не создаются.

**Критерии приёмки:**
- **Given** Bluetooth выключен и показано предупреждение, **When** пользователь отказывается включать Bluetooth, **Then** страница подключения не открывается и сессия не создаётся.

### FR-CONN — предусловия транспортов (сквозное требование)

Проверка выполняется **до** создания сессии/QR/Room Link:

| Транспорт | Предусловие | При невыполнении |
|---|---|---|
| Wi-Fi / Local Network | Wi-Fi-модуль включён и есть подключение к сети | Запрос включения → отказ: сообщение «Передача невозможна, пока не включён Wi-Fi» |
| Bluetooth | Bluetooth включён | Предложение включить → отказ: отмена сценария |
| Интернет | Есть активное сетевое подключение (любое) | Сообщение об отсутствии подключения; сессия не создаётся |

«Отсутствие интернета» = отсутствие активного подключения, а не качество канала/баланс тарифа — такие проверки не выполняются. Хотспот-fallback — отдельный сценарий, вне scope этого требования.

## BUG-06. Отсутствует Room Link на iOS

**Окружение:** отправитель iOS 18.5.1, все транспорты.

**Фактический результат:** на экране ожидания подключения iOS нет Room Link для ручного ввода на desktop (на desktop Room Link есть).

**Ожидаемый результат:**
1. На экране ожидания подключения iOS (Wi-Fi, Bluetooth, интернет) отображается Room Link с кнопкой «Копировать»; состав данных идентичен desktop-версии.
2. Отображение Wi-Fi-адреса отправителя удаляется из UI на всех платформах (desktop — BUG-03, iOS — здесь). Внутренняя логика соединения не затрагивается.

**Критерии приёмки:**
- **Given** создана сессия на iOS по транспорту T (T ∈ {Wi-Fi, Bluetooth, интернет}), **When** открыт экран ожидания, **Then** отображается Room Link; кнопка «Копировать» помещает его в буфер обмена.
- **Given** скопированный на iOS Room Link, **When** он введён на desktop, **Then** desktop подключается к сессии.

## BUG-07. Системный пикер не фильтрует по типу, выбранному в приложении

**Окружение:** обе версии. Платформенные диалоги: Finder (macOS), Проводник (Windows), файловые менеджеры iOS/Android.

**Требование:** выбор типа содержимого в приложении (папка / файлы / фото и видео) остаётся; открываемый затем системный диалог обязан допускать выбор **только** соответствующего типа:
- выбрано «Папка» → можно выбрать только папку;
- выбрано «Файлы» → только файлы (фото и видео недоступны);
- выбрано «Фото и видео» → только фото и видео.

**Критерии приёмки:**
- **Given** в приложении выбран тип X (X ∈ {папка, файлы, фото и видео}), **When** открыт системный диалог выбора, **Then** элементы типа ≠ X недоступны для выбора на всех поддерживаемых платформах.
- **Given** платформа не позволяет выразить фильтр системными средствами, **Then** выбор неподходящего типа отклоняется с понятным сообщением (пост-фильтрация).

**Для разработки:** сейчас `pickFiles(allowMultiple: true)` без ограничения типа (`file_picker_page.dart`), папка — `getDirectoryPath()`, медиа — отдельный `media_picker_page.dart`. Фильтр «любые файлы, кроме медиа» системными средствами невыразим (file_picker: `FileType.any`/`media`/`custom`) — закрывать пост-фильтрацией с сообщением либо белым списком расширений.

## BUG-08. Нет таймера актуальности сессии

**Окружение:** iOS-отправитель, Bluetooth (зафиксировано там); требование едино для всех экранов ожидания подключения.

**Ожидаемый результат:** на экране ожидания подключения любого транспорта отображается обратный отсчёт времени жизни сессии. TTL сессии единый для всех способов передачи: **5 минут** (300 с). По истечении: сессия инвалидируется, показывается сообщение об истечении с кнопкой «Обновить» (создаёт новую сессию, таймер сбрасывается).

**Критерии приёмки:**
- **Given** создана сессия любого транспорта, **When** открыт экран ожидания, **Then** виден обратный отсчёт от 5:00.
- **Given** отсчёт дошёл до 0:00, **Then** сессия инвалидирована (подключение по ней невозможно), показано сообщение и кнопка «Обновить».
- **Given** нажата «Обновить», **Then** создана новая сессия, отсчёт идёт от 5:00.

**Для разработки:** `AppConstants.sessionTimeoutSeconds = 300` уже используется на Wi-Fi-экране (`qr_display_page.dart`) — распространить на Bluetooth и интернет. Выяснить назначение `qhtpSessionTimeoutSeconds = 1800`: если это TTL ожидания подключения — привести к 300 с; если окно возобновления передачи — не трогать и не путать с TTL сессии.

## BUG-09. Кнопка «Отмена» недоступна для нажатия (Bluetooth-экран)

**Окружение:** отправитель iOS 18.5.1, экран Bluetooth-подключения.

**Фактический результат:** кнопка «Отмена» смещена вниз за пределы доступной области, нажатие невозможно.

**Ожидаемый результат:** кнопка «Отмена» полностью видима и нажимается на всех поддерживаемых размерах экрана iPhone (учитывая safe area и минимальную поддерживаемую диагональ).

**Критерии приёмки:**
- **Given** экран Bluetooth-подключения на минимально поддерживаемой диагонали, **When** экран открыт, **Then** кнопка «Отмена» целиком в видимой области; **When** нажата, **Then** сессия отменяется, пользователь возвращается на экран выбора способа.

## BUG-10. Время формирования QR зависит от объёма данных

**Окружение:** обе версии, оба направления, все транспорты.

**Фактический результат:** при объёме > 50 МБ время до появления QR растёт с ростом объёма (500 МБ ≈ 10–15 с); для десятков ГБ / папок в 1 ТБ неприемлемо.

**Ожидаемый результат:** создание сессии и отображение QR/Room Link не зависят от объёма выбранных данных. **Целевой порог: ≤ 2 с при любом объёме.** Полная подготовка данных (подсчёт размера, хеширование, индексация папки) выполняется асинхронно после показа QR, с отображением прогресса подготовки; старт передачи блокируется до её завершения.

**Критерии приёмки:**
- **Given** выбран источник объёмом V (V ∈ {50 МБ, 10 ГБ, папка 1 ТБ}), **When** пользователь инициирует отправку, **Then** QR/Room Link отображается ≤ 2 с независимо от V.
- **Given** QR отображён, а подготовка не завершена, **When** получатель подключается, **Then** передача не стартует до готовности данных; обе стороны видят статус подготовки.

**Для разработки:** сохранить контроль целостности — если хеш используется для верификации, перейти на потоковый подсчёт во время передачи.
